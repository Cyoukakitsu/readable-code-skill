# 詰め込み

原則: 基準は新しい構文か古い構文か、短いか長いかではない。読み手が頭の中でもう一段「翻訳」しなければならないかどうかだ。

短くて明快なもの（単純な `map` や `filter`、オプショナルチェーン）は良い。短いが密度が高すぎるものは良くない。

## 兆候

- おおむね 5 段以上のメソッドチェーン。特に `filter` / `map` / `reduce` / `flatMap` が混ざり、途中の値に名前がないもの
- ネストした三項演算子
- 普通のループなら上から下へ読めるのに、オブジェクトの組み立てや副作用のために使われている `reduce`
- 演算子の優先順位、短絡評価による副作用（`cond && doSomething()`）、暗黙の型変換に頼った凝ったワンライナー

## 修正案の出し方

- チェーンを分割して途中の結果に名前を付ける（`const activeUsers = ...`）か、普通の `for...of` ループに書き直す。
- ネストした三項演算子は、`if` や早期 `return`、またはルックアップ用のオブジェクトに置き換える。
- すでに短く明快なコードを、チェーンだというだけで分割するよう提案しない。
