# 回帰テスト

スキルを変更したとき、変更前に抜けていなかった指摘が抜けていないか、誤検出が増えていないかを確かめる。

## 構成

- `fixtures/` — レビュー対象のコード。実プロジェクトの修正前コードと、指摘が出てはいけないコード（`clean-route`）
- `expected.json` — 各サンプルで出るべき指摘。`passes` 以外は変更しない
- `baseline.md` — 実行結果の記録

## 実行手順

1. サンプルごとに、新しいサブエージェントを 3 回起動する（LLM の出力はぶれるので 1 回では判断しない）
2. 各回に次を渡す：スキル本体と `references/` を読み、`targets` をレビューする。ファイルは編集しない。期待値（`expected.json`）は見せない。他のプロジェクトファイルは参照できないので、確認できないことは `unverified` にする
3. 出たレポートを `expected` と照合し、各項目が 3 回中何回出たかを数える
4. `clean-route` は must / should が 1 件でも出たら、その回は失敗

## 判定

- 項目の `passes` は 3 回すべてで `min_severity` 以上の重要度で出たときだけ `true`
- 変更後は同じ手順をもう一度やり、基線より悪化していないかを比べる
- 通らないからといって、`expected.json` の期待値を消したり重要度を下げたりしない

## 注意

- 期待値は、同じモデルによる過去のレビューから作った。独立した正解ではない点に注意する
- サブエージェントを呼ぶので実行に費用がかかる。サンプル 3 つ × 3 回 = 9 回が目安
